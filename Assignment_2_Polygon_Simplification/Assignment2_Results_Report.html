Instructions

This report is organized to satisfy the experimental-evaluation requirements of the assignment.

  • Dataset Goals explains what each dataset targets and why it is difficult.
  • Overview keeps the exact values from the output files for area, displacement, running time, and peak memory.
  • Efficiency shows running time vs input size and peak memory vs input size, together with fitted scaling laws.
  • Displacement compares displacement quality, final vertex counts, displacement vs input size, and displacement vs target vertex count.
  • Custom Cases explains the purpose of the custom stress tests.
  • Discussion interprets the main trends rather than only listing raw values.

Requirement (c): areal displacement is examined both against the provided outputs and against requested target vertex counts. The report therefore includes direct comparisons, final-vertex comparisons, displacement-versus-input-size behavior, and explicit target sweeps.

What the Custom Test Cases Target

These custom datasets are meant to expose failure modes that are easy to miss on ordinary benchmarks. They are especially useful for discussing robustness under narrow clearances, many holes, high vertex counts, and near-degenerate geometry.

output_custom_combined.txt

Targets: Combined stressors

Why difficult: Useful for checking overall robustness rather than one isolated failure mode.

Observed outcome: 1500 final vertices, 5.090823e-02 displacement, 127.42 ms runtime, 13.30 MB peak memory.

output_custom_high_hole.txt

Targets: Large number of holes

Why difficult: Many interior rings increase the amount of topology checking per collapse.

Observed outcome: 350 final vertices, 1.080000e+02 displacement, 2.72 ms runtime, 3.94 MB peak memory.

output_custom_high_vertex.txt

Targets: High vertex count

Why difficult: A custom scalability stress test.

Observed outcome: 500 final vertices, 3.649223e-01 displacement, 1291.81 ms runtime, 31.27 MB peak memory.

output_custom_narrow_gaps.txt

Targets: Narrow gaps

Why difficult: The geometry leaves little room for placement error.

Observed outcome: 155 final vertices, 2.115082e-14 displacement, 11.98 ms runtime, 4.45 MB peak memory.

output_custom_near_degeneracies.txt

Targets: Near-degeneracies

Why difficult: Almost-collinear features expose unstable predicates.

Observed outcome: 100 final vertices, 9.451948e+00 displacement, 37.05 ms runtime, 7.23 MB peak memory.

Discussion and Interpretation

The provided benchmark set contains 15 directly comparable cases, and the current implementation is equal to or better than the given displacement on 15 of them.

The largest observed improvement is on output_original_09.txt, where displacement drops from 1.491307e+09 to 1.268855e+09.

The scaling plots are consistent with an O(n log n) runtime trend and an O(n) memory trend. The fitted coefficients are 4.113409e-03 for runtime and 3.659203e-02 for memory, with R² values of 0.7448 and 0.0000.

The heaviest workload in the current report is output_original_09.txt at 21360.29 ms, while the largest peak memory is on output_original_09.txt at 854.68 MB.

Among the custom datasets, output_custom_high_vertex.txt appears to be the toughest in practice. It targets High vertex count and finishes with 3.649223e-01 displacement after 1291.81 ms.
